# 安卓 APK 一键打包（TapTap 官网包）

把现有的 Web 游戏用 **Capacitor** 包成安卓 Release APK，上传 TapTap。

## TL;DR

```bash
npm run apk          # 打当前版本号的 release APK
npm run apk:bump     # VersionCode +1 后再打包（发新版本时用）
```

产物在 `dist-apk/二十五时便利屋-v<名>-<码>.apk`，直接上传 TapTap「官网包」。

---

## 关键约束（务必遵守）

| 项 | 取值 | 说明 |
|----|------|------|
| **包名 applicationId** | `com.ershiwushi.bianliwu` | **上线后永不可改**。在 `capacitor.config.ts` 与 `android/app/build.gradle` 中。 |
| **架构** | 架构无关 APK | Capacitor 应用无原生 `.so`，天然兼容 64+32 位；**绝不可只 32 位**。脚本不设 `abiFilters`。 |
| **VersionCode** | 整数 > 0，且 ≥ 线上版本 | 高于线上时提示用户更新。单一来源：`android/version.properties`。 |
| **签名 keystore** | `android/keystore/xiashan-release.jks` | **上线后不可更换，丢失=无法更新游戏**。务必离线备份，密码见 `keystore.properties`。 |

> `keystore.properties`、`*.jks`、`dist-apk/` 都已在 `.gitignore`，**绝不入库**。

## 版本号怎么管

唯一来源是 `android/version.properties`：

```properties
VERSION_CODE=1        # TapTap 比对用，每次发版必须比线上大
VERSION_NAME=1.0.0    # 展示给玩家的版本名
```

- `npm run apk:bump` 会自动把 `VERSION_CODE` +1。
- 改展示版本名：`bash tools/build-apk.sh --bump --version-name 1.1.0`
- `build.gradle` 在打包时读取该文件，不要再手改 gradle 里的版本号。

## 完整命令

```bash
tools/build-apk.sh                      # Web 构建 → cap sync → release APK
tools/build-apk.sh --bump               # 先 VersionCode +1
tools/build-apk.sh --version-name 1.2.0 # 设展示版本名
tools/build-apk.sh --no-web             # 跳过 Web 构建，用现有 dist/
tools/build-apk.sh --aab                # 额外产出 AAB（Google Play 用，TapTap 不需要）
```

## 工具链（已在本机安装）

- **JDK 21** — Homebrew `openjdk@21`（`/opt/homebrew/opt/openjdk@21`）。**Capacitor 8 必需 JDK 21**，17 会报「无效的源发行版：21」。
- **Android SDK** — `~/Library/Android/sdk`（cmdline-tools / platform-tools / platforms;android-36 / build-tools 35.0.0+36.0.0）

脚本会自动定位 `JAVA_HOME` 与 `ANDROID_HOME` 并写 `android/local.properties`，无需手动配环境变量。

换机器重装时：
```bash
brew install openjdk@21
# 下载 cmdline-tools 到 ~/Library/Android/sdk（dl.google.com 被墙时用腾讯镜像
#   https://mirrors.cloud.tencent.com/AndroidSDK/commandlinetools-mac-*.zip），再：
export SDKMANAGER_OPTS="-Dsdk.test.base.url=https://mirrors.cloud.tencent.com/AndroidSDK/"
sdkmanager "platform-tools" "platforms;android-36" "build-tools;35.0.0" "build-tools;36.0.0"
```

## 换 App 图标

**唯一图标源**：`public/app-icons/app-icon-1024.png`（方形 1024×1024）。
**每次 `npm run apk` 都会自动从这张图重新生成各密度 launcher 图标**（build-apk.sh 的 [0/3] 步骤），
所以换图标只需替换这一个文件，再打包即可——不必手动跑生成器。

需要单独重生成（不打包）时：

```bash
swift tools/make-android-icons.swift public/app-icons/app-icon-1024.png android/app/src/main/res
```

生成物：各 `mipmap-*` 下的 `ic_launcher.png`（方形满版）、`ic_launcher_round.png`（圆形遮罩）、
`ic_launcher_foreground.png`（自适应前景，API 26+ 由系统按设备形状裁切）。满版图标在圆形/
squircle 遮罩下边角会被裁，重要内容（如「25」标识）尽量靠中心。

## 改了游戏内容后怎么发新版

1. 正常改代码、本地 `npm run dev` 验证。
2. `npm run apk:bump`（VersionCode 自动 +1，确保高于线上）。
3. 把 `dist-apk/` 里新生成的 APK 传到 TapTap。

---

## 备份提醒

**首次出包后立刻做这两件事，且只做一次：**
1. 把 `android/keystore/xiashan-release.jks` 复制到离线安全位置（云盘私密 / U 盘）。
2. 把 `keystore.properties` 里的密码单独记到密码管理器。

keystore 丢了 = 这个包名再也无法发布更新，只能换包名重新上架（用户需卸载重装）。
