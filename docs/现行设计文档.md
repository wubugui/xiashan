# 《二十五时便利屋》（都市便利屋 · 分池抽卡）— 现行设计文档

> 版本 v1.4（2026-06-11）。本文档为项目唯一现行设计，取代已废弃的《废物下山》线性 AVG（旧文档见 `deprecated/`）。
> 文中所有机制均以当前代码实现为准（`src/engine/shopEngine.ts`、`src/store/useShopStore.ts`、`src/pages/Shop.tsx`、`src/data/types.ts`）。
> v1.2 变更：重做好感与关系系统（见 6.3）——好感独立存储、心动 UP、关系阶段制、取消"委托完成自动入伙"。
> v1.3 变更：五分池合并为双频道（见 3）——人物并入统一补给池，6% 低概率 + 15 抽硬保底，人物券货币删除。
> v1.4 变更：委托板取代抽委托（永不卡关），委托改子目标制（剧情分幕穿插跑图），新增顺手单；委托券货币删除。

## 1. 产品概述

一个"抽卡 + 跑图办事"的 Roguelike-lite。核心幻想：**你是「二十五时便利屋」的老板**——一天只有二十四小时，而这家店开在不存在的第二十五小时，专门接住那些被城市时间表漏掉的人和麻烦。每天接一个委托，在城市里跑 5 段路线，靠抽到的卡把麻烦一个个解决，攒够"信任"就完成委托，解锁委托人（美少女）的好感与专属影像。

> 店名「二十五时」同时是世界观钩子：所有女主角的委托，都发生在她们"二十四小时之外"走投无路的时刻。

与已废弃的剧情 AVG 的本质区别：**没有写死的剧情线，所有内容都是"卡 × 场景"的组合**。

- **架构原则**：内容是"加法"录入（往数据表里加对象），可玩性是"乘法"增长（引擎自动排列组合）。一次开发，配置续命。
- **内容即数据**：`commissions / characters / serviceCards / locations / videos` 全部是 JSON 配置（`src/content/*.json`），代码只负责渲染和逻辑调度。

## 2. 一局循环（核心，v1.4）

```
开始营业 → 委托板 3 选 1 接单（播开场幕） → 看子目标规划路线（3 选 1 地点）
   → 在对的地点用对的卡打热点 → 子目标完成即播一幕剧情（剧情穿插跑图）
   → 顺手单随手赚普通券/资金 → 全部子目标完成 → 「交付」播结局幕（信任分好坏结局）
   → 结算 → 未交付则委托逾期，明日可重接（永不卡关）
```

### 2.1 局内资源（`useShopStore` 初始值）

| 资源 | 初始 | 作用 | 归零后果 |
|------|------|------|----------|
| 时间 time | 13 | 每个热点/赶路消耗 | **当日失败** |
| 精力 energy | 8 | 每个热点/赶路消耗，咖啡可补 | **当日失败** |
| 口碑 rep | 5 | 危机处理失误会扣 | **当日失败** |
| 资金 money | 20 | 买咖啡补精力、部分热点消耗 | 不致败，但失去补给手段 |
| 信任 trust | 0 | **目标资源**，攒到委托 `need` 即委托达成 | — |

### 2.2 节奏与结算

- `step` 1→5：每完成一个地点 `finishLocation()`，step+1、时间-1、精力-1，并重掷下一段 3 条路线；step>5 触发 `endDay()`。
- 无卡可打时可"普通推进"（`normalAdvance`）：有委托时 信任+1/时间-2/精力-1；无委托时 资金+2/时间-1/精力-1。
- **交付结算**（剧场结局幕，`handleTheaterComplete`）：
  - 好结局（信任 ≥ need+5 过 gate）：**普通券+4、口碑+1**，并执行 `rewardEffects`（角色好感 +20~30、灵石、set_flag 解锁视频）。
  - 坏结局：补偿普通券 +1（委托视为已了结，flag 不设，日后可在板上重现）。
- **未交付**（跑满 5 段或资源耗尽）：委托转入**逾期**——次日委托板可重接（口碑 -1），最多拖 2 天；补偿普通券 +1。

### 2.3 委托板 / 子目标 / 顺手单（v1.4）

**委托板**（根治卡关）：委托券已删除（旧存档 1:1 折普通券）。每天开局委托板自动挂出 **3 张委托选 1 接单**（逾期单优先占位，已完成的委托靠后补位），接单免费——每天必有委托可做，卡关链路（券断供）不复存在。接单瞬间播开场幕，即"接单仪式感"。

**子目标制**（根治"点几下完事"）：每个委托带 2~3 个子目标（`commissions.json objectives`），格式：在【locTag 类地点】的匹配热点上打出 need 类型的卡（万能卡通吃）。设计效果：
- 选路线从"随便走"变成**规划**（"第三段必须找职场类地点，手里得留流程卡"）；
- 每完成一个子目标**立刻播对应剧场幕**（`scene: {start, stopBefore}`，graph 按幕复用），剧情穿插在跑图里；
- **交付条件 = 全部子目标完成**；信任只决定结局好坏（gate 阈值 = need+5，统一信任口径：热点+子目标+幕内挑战全部累计）。情报卡「城市情报」刷新路线，顺势成为找地点的核心卡。

**顺手单**（跑图填充）：每天 2 张通用模板小委托（`sideJobs.json`，8 模板池），完成方式同子目标（对的地点打对的卡），奖励普通券/资金——普通券的稳定日常来源，支撑补给池抽卡频率。

## 3. 双频道抽卡（v1.3 重做）

> v1.3 变更：原"五分池"合并为**双频道**。动机：人物单独成池时出货是确定性的（一券一人物），没有"出金"的随机惊喜；五个入口也稀释了抽卡仪式感。

| 频道 | 抽什么 | 消耗 | 产物 |
|------|--------|------|------|
| 委托板 | "今天帮谁"——3 选 1 接单 | 免费 | 当日任务（子目标+剧场分幕，见 2.3） |
| 便利屋补给 | 人物·技能·便利·情报混合池 | 1 普通券 | 见下方概率表 |

**便利屋补给池**（配置在 `gacha.json supplyPool`，引擎 `gachaEngine.pullSupply`）：

| 出货 | 概率 | 说明 |
|------|------|------|
| **人物卡** | **6%** + **15 抽硬保底** | 出金时刻：稀有度按 SSR 3%/SR 32%/R 65% 掷(SSR 刻意压低)，心动UP 权重生效，触发出货演出；保底计数（`supplyPityCounter`）只被人物重置，UI 实时显示"保底 X 抽" |
| 技能卡 | 40% | 一次性手牌 |
| 便利卡 | 20% | 一次性手牌 |
| 情报卡 | 14% | 一次性手牌 |
| 消消乐提示券 | 8% | 计数道具（`hintTokens`）：每日 3 次免费提示用完后消耗 |
| 灵石小包 | 9% | +60 灵石 |
| 灵石大袋 | 3% | +300 灵石，**稀有特写**（金光开箱+彩带，与 SR 卡同档演出） |

所有非人物出货均走「开箱演出」（`SupplyReveal`：悬念抖动 → 翻牌揭示），稀有档（SR 卡/灵石大袋）金光特写+彩带，为非出金抽次制造小爽点。

补给池有两个入口共享同一保底计数:店内「便利屋补给」(1 普通券/抽)与首页抽卡页(灵石 100/单抽、900/十连,卡产物进入手牌且跨天保留)。

关键设计：**人物是池中的低概率大奖**——平时抽到的消耗卡维持局内玩法运转（保底"不亏"），人物出货是真正的惊喜峰值，保底倒数提供"快出了"的期待感。人物券/委托券货币均已删除（旧存档按 1 人物券 = 2 普通券、1 委托券 = 1 普通券折算并入）。

## 4. type 匹配系统（玩法引擎）

最省成本的核心机制（`shopEngine.ts`）：

- 12 种服务标签 `ServiceTag`：流程 / 表达 / 技术 / 安抚 / 补给 / 宠物 / 情报 / 观察 / 维修 / 路线 / 恢复 / 万能。
- 每个场景热点 `spot` 有 `need:['流程','技术']` 标签需求；每张卡有 `type`。
- `isMatch()`：卡 type 命中热点 need → **匹配**。

| 出牌 | 信任 | 附加 |
|------|------|------|
| 人物卡·匹配 | +3 +（Lv-1） | 减免热点成本；表达/宠物→口碑+1，补给→资金+2，安抚→精力+1；命中 `special` 则播专属爽文本 |
| 人物卡·不匹配 | +1 | 仍可用，通用文案 |
| 技能卡·匹配 | +3（宠物类 +4） | 减免成本；维修抵口碑损失，技术抵时间损耗，安抚精力+1 |
| 万能卡（临时人脉电话） | **+5** | 永远匹配，口碑+1，专属爽文本 |
| 情报卡 | +1~+2 | 减免成本 / 刷新路线 / 抵消危机负面 |
| 不出牌 | 按热点 base 结算 | danger 热点会净扣资源 |

- `special` 字段：特定角色 × 特定热点的专属台词（如祁宁在写字楼前台）。**这是唯一手写内容，是点缀不是主体**，也是后续填内容的主要抓手。

## 5. 委托剧场（图驱动 AVG 演出，v1.4 分幕化）

带 `graph` 的委托进入全屏剧场（`CommissionTheater.tsx`），剧情是有向图而非线性脚本（`types.ts CommissionGraph`）。v1.4 起支持**分幕播放**（`scene: {start, stopBefore}`）：接单播开场幕（intro→b1），每完成一个子目标播一幕（b2/b3/b4），交付播结局幕（gate→ending）；幕内挑战的信任实时写回局内信任，跨幕累计。

- `dialogue`：播对白跳 next；`branch`：按信任阈值 `trustGte` 分流；`ending`：`success` 决定奖励路径。
- `challenge`：出牌三档判定，每档自带反应对白 + 信任/情绪变化 + 各自 next（可分支可汇合）：
  - **perfect**（打出匹配卡）信任+3 / **ok**（非匹配卡）+1 / **poor**（不出牌）+0；
  - `danger:true` 的危机幕，poor 档额外扣口碑（`repPenalty`）。
- 客户情绪 Mood（焦虑→平静→感动→信赖）随判定流转，纯演出用。
- 范本：`interview`（江夏·面试前的最后十分钟），约 10 节点 × 3 档反应，已完整可玩。

### 6.1 单女主游戏流程（八人同构）

```
邂逅期（未持卡）：
   委托板接下她的委托（不要求持有） → 子目标推进 + 剧场分幕 → 交付达成
   → set_flag + 好感+20~30（独立字典，永不丢失） + 灵石 → 解锁专属影像 s1（委托篇）
   → 好感攒到 40 → 补给池人物出货触发【心动 UP】（同稀有度内权重 ×4）
出金（唯一入伙通道）：
   补给池抽到她（6%+15抽保底） → 入伙演出（出货文案承认此前积累："那几次委托……我都记得"）
养成期（持卡后）：
   → 日常：匹配热点出战（信任+3+Lv，special 专属台词）/ 每日互动 / 送礼 → 好感持续积累
   → 角色页推进关系阶段（好感门槛递增 + 每角色每日一阶） → 阶段 2 解锁专属影像 s2（日常篇）
   → 人物卡升 Lv → 匹配信任加成提高，高 Lv 解锁新互动对话
```

现状对照：八位女主对应委托均已有 `graph`，并各有 s1/s2 视频条目；mp4 素材尚未落位。走失猫委托（`cat`）的 target 是小鬼（N·宠物），保留不变。

### 6.2 手机模拟器（正式系统：委托外围层）

都市游戏不能没有手机。`PhoneSimulator`（微信/电话/短信/浏览器）**整体保留**，从 AVG 的剧情工具改为便利屋循环的**外围情感层与信息层**——它的事件引擎（`phoneScheduler.ts` + `phone-events.json`，条件驱动：`flag_set` / `affinity` / `has_character` 等）与委托 flag、好感值天然兼容，几乎零改造接入：

| 手机功能 | 在便利屋循环中的角色 | 触发示例 |
|----------|----------------------|----------|
| 电话/短信 | **接单仪式感**：委托频道抽到委托 = 客户来电/短信下单 | 抽到 live 委托 → 云晓蔻来电"周年直播快炸了" |
| 微信 | **好感外围**：委托完成后委托人道谢、发红包（灵石）；好感节点解锁闲聊事件，预告 s2 影像 | `flag: commission_interview_done` → 江夏微信"我入职啦！"+ 红包 |
| 短信 | **结算爽感**：日结算后银行到账通知（委托报酬） | "您尾号 8888 的账户入账 ¥300" |
| 浏览器 | **情报网络的延伸**：城市新闻预告明日地点/热点倾向，呼应情报卡 | "本周地铁线检修"→ 明日地铁站 danger 热点概率提示 |
| 通知横幅 | 跑图中收到消息提示，不打断主循环，回家（日结算后）再看 | — |

角色的 `phonePersonality`（微信语气/回复速度/口头禅，characters.json 已有字段）继续生效——8 位女主每人一套手机人格，是低成本的人设放大器。

### 6.3 好感与关系系统（v1.2 重做）

**动机**：旧实现把好感挂在 `OwnedCharacter` 上，给未持有角色发好感会静默丢失；Shop 曾用"委托完成自动 `addCharacter`"规避，但这等于绕过抽卡白送角色，直接稀释了本作最高爽点——**抽到美少女**。v1.2 按四条原则重做：

1. **积累端统一**：从游戏第一分钟起，"对她好 → 同一根好感条上涨"，规则唯一，不随持卡状态改变（避免"同一行为产出不同货币"的认知分裂）。
2. **解锁端分阶段**：门槛挂在内容上而非积累规则上。未持卡时好感的唯一出口是心动 UP；持卡后走关系阶段制。
3. **持有只能来自抽卡**：委托完成不再自动入伙。帮过 ≠ 拥有，出金是唯一入伙通道。
4. **一切为出金蓄力**：邂逅期攒好感却碰不到她（差一层窗户纸），出金瞬间由入伙演出兑现，之后阶段制保证养成跑道完整。

**数据结构**（`usePlayerStore`，旧存档自动迁移）：

- `affinityMap: Record<characterId, number>`——好感独立字典，与持有解耦，**无上限**（好感源含有限手工委托，封顶+溢出转化会永久烧掉有限矿；跑道问题由阶段制承担，不靠封顶）。
- `relationshipStages: Record<characterId, number>`——当前关系阶段。
- `dailyActions: Record<key, date>`——互动/推进阶段的每日限频记录（按自然日）。

**好感来源分两层**（有限源给爆发，可再生源保证永远有路可涨）：

| 来源 | 数值 | 性质 |
|------|------|------|
| 手工委托 rewardEffects | +20~30 | 有限源，大额爆发 |
| 手机事件选项 | +1~3 | 半有限源（事件一次性） |
| 日常互动 摸头/聊天（持卡后，每日各 1 次） | +2 | 可再生 |
| 送礼（持卡后，每日 1 次，花灵石 50） | +5 | 可再生，兼灵石回收 |

**心动 UP**（邂逅期好感的出口）：好感 ≥ 40 且未持有的角色，补给池人物出货时同稀有度内抽取权重 ×4。卡池**不做硬门控**（开局池子会空），用 up 实现"她在等你"。

**入伙演出**：抽到已有好感的新角色时，出货追加专属承认文案——把邂逅期的积累在叙事上兑现，是出金高潮的放大器。

**关系阶段**（持卡后的内容闸门，配置在 `src/content/relationship.json`，默认 5 阶可按角色覆写）：

| 阶段 | 名称（默认，8 女主各有覆写） | 好感门槛 | 解锁 |
|------|------|----------|------|
| 1 | 交换联系方式 | 40 | 基础互动全开 |
