# 《25时便利屋》叙事玩法迭代 V1：凌晨一点的纸箱

> 分支：`feat/interactive-city-stories-v1`；基线：`main@ecfd0e8`。
>
> 这是一个**可对照的交互叙事垂直切片**，不是完整重构。主分支、原抽卡概率、角色池、老委托、原存档均不直接改动。

## 想验证的问题

原便利屋玩法的高频动作是选路线、点热点、按服务标签打牌。不同女主故事虽然文案不同，但行动基本同构。此次增加不同类型的体验：玩家主动检查证据、推断事件、调用已抽到的角色能力、承担信息不完整和不同处理方式的后果。

玩法必须**既有情节悬念，又有可执行操作**，不能只换成长对白。

## 首个事件《凌晨一点的纸箱》

涉及陈小满、祁宁、沈疏桐、许念；玩家在便利屋听到小满被网传“偷快递”指控。

1. 调查签收单、删减监控、录音草稿。至少两项证据方可提交一次推断。
2. 推断为盗窃、炒作或救助。推断提交后不允许随意重选。
3. 玩家选择完整公开录像、私下协调，或者在证据充分时，提交脱敏的正式核实。
4. 三个结局结果不同：立即澄清会暴露住户隐私；正式澄清更稳妥但耗费时间并影响小满转正；私下协调平息争议但无法还她清白。
5. 结局写入 `city_midnight_parcel_*` 标志与原 `affinityMap`，发放抽卡资源，已抽到的相关角色收到微信消息。结局和奖励只能结算一次。

### 抽卡如何仍然重要

- **保留双抽卡入口及原概率**，不调整 `gachaEngine.ts`。
- 已抽到祁宁，查看签收单时可获得正式流程补充，掌握两项证据且推断正确即可核实。
- 已抽到沈疏桐，查看监控时可获得专业查证补充，掌握两项证据且推断正确即可核实。
- 已抽到许念，查看语音时可见其专属解释。她不替玩家决定处理结果。
- 未抽到这些角色仍能解锁正式核实：查看全部三项证据并正确推断。
- 事件结束获得普通券与月光，回流原角色抽卡；人物和社会关系先存在，抽到后再打开私信交互。

### 页面/入口

- 首页新增 **「午夜来访」** → `/#/city-case/midnight-parcel`。
- 原 **「月光开店」** 和 **「星愿邂逅」** 入口保持原样。
- 原新手教学未完成时，该独立事件不开放，不改变教学脚本。
- 手机采用原 `usePlayerStore.addPhoneMessage` 数据形态；结算直接在 Store 中一次写入，防止重复领奖与半更新。
- 事件进度不用新的 Store 字段，依赖既有 `flags`，避免本次引入存档结构迁移风险。

## 开发文件

- `src/engine/cityCase.ts`：纯数据与规则，含三证据、三推断、三结局及可达性条件。
- `src/pages/CityCase.tsx`：移动端优先的现场调查、证据查阅、一次性判断、结局与角色反馈页面。
- `src/store/usePlayerStore.ts`：新增 `completeCityCase` 原子结算操作（不改原有持久字段结构）。
- `src/App.tsx` 与 `src/pages/Home.tsx`：独立路由、首页入口。
- `tools/tests/city-case.test.mjs`：纯规则回归测试。

## 执行/验收

切换本分支后：

```bash
npm ci
npm run check
npm run content:validate
npm run test:city-case
npm run build
npm run dev
```

用已有完成教学的存档，在首页点击「午夜来访」，至少完成以下验收：

- **无角色测试**：只读两条证据并猜对，只能公开/协调；补齐三条证据，正确推断后可以正式核实。
- **角色能力测试**：持有祁宁+签收单或沈疏桐+监控时，阅读两条证据并正确推断即可使用正式核实路径。
- **误判测试**：提交不正确推断，即使抽到了SSR也不能凭空使用正式核实路径。
- **存档测试**：只读一条证据退出再进入，证据应保留；提交推断后刷新页面，不得重选。
- **结算测试**：连续点击确认仍只奖励一次；刷新后只见既定结局，不能重复获得资源。
- **内容测试**：不同结局改变小满、祁宁、沈疏桐的好感，已持有角色收到微信；未持有角色的好感也会保留。
- **回归测试**：仍可进入传统开店、抽卡、角色养成、手机、小游戏；角色稀有度和保底没有变化。
- **移动端检查**：Android 刘海屏、底部手势区、竖屏三列证据在小屏自动堆叠，不遮挡返回与确认。

## 已知限制和下一版方向

- 首次只实现**一个有持续后果的交叉事件**，不是八位女主各自完整主线，更不能称为全游戏已改造。
- 后果已写入持久 flag、好感和手机，尚未为所有既有委托编排对这些 flag 的具体反应。
- 线索阶段仍是点击查看而非完整桌面物证推理，适合验证节奏，暂不能替代未来更复杂的物件操作。
- 事件没有实时失败时钟、三维走动、NPC 行为树或者自由组合系统；这里依然采用**可审查的离线剧情分支**。
- 为避免未经审查的叙事污染，本次没有改动八条现有恋爱线、结局或抽卡经济平衡。
- 下一轮应优先：独立事件数据 Schema / 编辑器、跨事件条件消费、正式叙事物件交互、角色个人主线与交叉支线，最后再考虑缩减老式标签热点循环。

## 预期验收口径

不是“能否点完剧情”，而是：玩家能否复述冲突与证据；是否知道自己为什么能/不能采用某种处理手段；抽到的角色是否改变了实用操作；结局是否留下真实的关系后果；最终是否愿意继续参与下一个事件。
